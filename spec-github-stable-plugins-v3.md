# Spec: Per-plugin GitHub stable/latest for DSH (v3; Pro review pending)

## 1. Intent & Invariants
- Every operator-maintained plugin may have unlimited `X.Y.Z-rc.N` GitHub pre-releases; its dedicated repository has exactly one stable `latest` pointing to a tested `X.Y.Z` Release. `web-015` pins only an exact stable version and immutable verified `.tgz`, not a moving Git URL. A new `latest` does not silently alter a running profile.
- Repository-scoped `latest` cannot be per-package for a multi-plugin monorepo. Therefore a package can join this channel only after it has its **own approved repository** (public/private chosen separately by the operator), or remains a local/third-party baseline outside the channel. For `dsh-cpamc-limits`, extracting a package from private `ai-gateway` into a dedicated **private** repository is a proposed migration, not an authorized action; shared KeyGuard code must be licensed, minimized, tracked, and tested as an explicit dependency/vendored source, never reached through `../../../keyguard`.
- Normative inventory: `github-release-inventory.json`, 14 ordered bundles + 8 other direct dependencies. It is an *observed, provisional* inventory, not proof of ownership. Release eligibility requires desired=enabled, operator control/maintained fork, verified license and provenance, clean committed source, passing tests, fully packed self-contained artifact, and explicit operator approval of repository/visibility.
- Exclude two in-box DSH bundles, upstream-owned/registry packages without an approved fork, and seven retired deps. Binary-only TTS/mobile remain local baselines: no GitHub stable/latest until source recovery (origin SHA, exact original license, committed reconstructed source and build-equivalence or documented divergence) and operator decisions on repository ownership/visibility.
- This document is architecture only. No commits/pushes, new repos, changes to GitHub settings, releases, live profile mutation, or service restarts are authorized by Pro review. The current production profile remains on already installed `*.local.*` archives until a separate migration is approved.

## 2. Interface / Data Contract
```text
One operator-approved GitHub repo per stable-eligible package.
Tag: signed annotated vX.Y.Z; package.json.version: X.Y.Z; uploaded asset:
  <name>-X.Y.Z.tgz (from npm/pnpm pack, never GitHub source tarball).
Pre-release: vX.Y.Z-rc.N, package version X.Y.Z-rc.N, prerelease=true,
  never installed in production.
Stable: draft=false, prerelease=false, immutable=true; expected asset, GitHub
  release attestation/digest + SHA256SUMS + provenance bound to peeled tag SHA.
Discovery: paginate all releases for the repo, filter complete verified stable,
  select max SemVer, require /releases/latest.tag_name == selected tag;
  mismatch, downgrade, same-version/different digest, missing release -> FAIL.
Production: download and validate to no-clobber, content-addressed local cache;
  stage whole profile; pin exact file:tgz + frozen lockfile; only with operator
  approval deploy, verify ordered bundle list, then separately approved restart.
```
- GitHub selection must not trust `target_commitish`, mutable `prerelease/latest` metadata, editable release titles, or `tarball_url`/`zipball_url` as package authority. Validate owner/repo/repository identity, signed tag peeled to commit, package name/version, uploaded asset SHA-256 (`asset.digest`, downloaded bytes, SHA256SUMS and provenance), size, GitHub immutable release attestation; fail closed on unverified signature, missing immutability, inconsistent `latest`, changed asset or tag. Enabling repository immutable releases **before** new Releases and updating `gh` (local 2.45.0 lacks `release verify`) or using an equivalent tested verifier are prerequisite gates, not assumed complete. GitHub Release metadata flags remain mutable even with immutable assets/tags.
- Release flow per package: clean source SHA and approved license → pinned Node/pnpm and frozen source lockfile → tests/build → pack and inspect real tarball/secret scan → signed tag referencing exact tree → draft release with `.tgz`, checksum, provenance → canary downloads the **same bytes** and verifies source/artifact → publish immutable release and verify attestation → independently resolve repo `/latest` against max strict SemVer. Do not rebuild or replace the asset after canary. Public/private GitHub feature compatibility is checked before relying on attestations.
- Read-only private release access: scoped GitHub App or fine-grained `Contents:read` token kept outside manifests/logs. Reject unexpected redirects with Authorization, non-expected repository owner, 401/403/404/rate limit/network failure; do not change production when offline. Cache path includes owner/repo/package/version/SHA and is published no-clobber after verification; old known-good stable versions retained for explicit rollback (exact tag+digest, human decision).
- DSH anti-resurrection guard: before any pnpm install, compare **every** package declaring `dsh.bundle` in direct dependencies with the exact ordered allowlist. The seven retired deps (`@deepseek-harness-tui/dsh-tui`, `dsh-better-sidebar`, `dsh-client-ui-session-id`, `dsh-homelab-overview`, `dsh-ouroboros`, `dsh-telegram`, `dsh-jev-supervisor`) are removed from manifest/lockfile **in a separate staged, explicitly approved migration**; preserve data and archived artifacts. Scan corresponding profile patch entries; after `dsh plugin install`, compare complete ordered bundle list, abort and restore snapshot on extra/removed/reordered items. Plain `dsh plugin` without this guard may resurrect six retired bundles; do not claim it safe until migration and negative tests pass.
- Current package gates: workspace-groups clean tracked `8718d7f` plus untracked docs/staging, public fork/MIT upstream attribution needed, existing prerelease `v0.1.0` no assets. Fleet Cleaner `bde39a8` published main still injects retired `betterSidebar`; three live fixes are dirty. `ai-gateway` private source has dirty cpamc client/manifest; currently shipped standalone KeyGuard files exist only in staged artifact; recover to clean source before separate private repo. TTS GPL and mobile MIT are binary/source-provenance-unverified. Other enabled operator packages (`dsh-ai-egress`, review/policy, OpenViking status) remain not eligible until license/source/build review; third-party packages remain upstream-only by default. No package currently has a certified stable Release.

## 3. Verification Checklist (Definition of Done)
- [ ] Operator resolves inventory unknowns, precise publication scope and visibility per package; all source-backed candidates have clean commit, upstream attribution, declared licenses and reproducible self-contained packed byte inventory. TTS/mobile excluded until recovery is proved, not silently published.
- [ ] Each eligible package's isolated repo can contain rc releases and at least one immutable stable; authenticated/public GitHub API `/latest` equals highest complete strict stable SemVer and is not an rc. Simulate out-of-order creation/manual latest choice and refuse drift.
- [ ] Signed tag/attestation, asset.digest, size/hash/provenance and clean downloaded canary pass; negative tests reject tag/asset/repo substitution, mutable release, stale same-version digest, downgrade, expired private auth, partial draft and offline GitHub.
- [ ] Exact ordered allowlist blocks all retired dependency resurrection; staged dependency cleanup + `dsh plugin` reconciliation, full Host/client canary and rollback are demonstrated without touching production.
- [ ] Only after separate user decisions: create repos/enable immutability/push source/publish stable Releases; later separately approve installation and one disruptive Web restart. Pro `OK` validates this plan alone, not these actions.
