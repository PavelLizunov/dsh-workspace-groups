# Spec: Безоткатная выкладка плагинов web-015 (v3)

## 1. Intent & Invariants
- What: устранить рассинхронизацию между рабочими плагинами и архивами, указанными в `web-015/package.json`; разрешить повторную материализацию pnpm без возврата старого кода.
- Канон — новый `.tgz` с уникальной внутренней SemVer-версией, путём и SHA-256; `node_modules` не редактируется как источник релиза, `link:` на живой репозиторий не считается релизом.
- **Множество D определяется инвентаризацией всех активных `file:*.tgz`**, включая host, client, metadata и assets. Сейчас подтверждён drift у `dsh-workspace-groups`, `dsh-client-ui-teratts`, `dsh-cpamc-limits` **и `dsh-web-mobile`**. Миграция запрещена, пока каждому элементу D не соответствует воспроизводимый актуальный архив либо явно согласованное исключение.
- Сохраняем все текущие исправления (цвет сессий, TTS, xAI и вкладки, mobile), профильные метаданные, Host-аутентификацию и порядок `dsh.profile.bundles`. Другие рабочие изменения в репозиториях не перезаписываем.
- Подготовка и тестирование не меняют боевой профиль и не прерывают чаты; фактическая установка и отдельный рестарт возможны только после явного решения пользователя.

## 2. Interface / Data Contract
```text
Artifact: /var/lib/dsh/.dsh/bundles/<name>-<new-semver>.tgz
Profile dependency: "<name>": "file:/var/lib/dsh/.dsh/bundles/<name>-<new-semver>.tgz"
Release record: archive SHA-256, package name/version, source commit or vendor diff,
                hashes/inventory всех packed runtime-файлов, toolchain, checks.
Rollback record: точная пара исходных profile/package.json + pnpm-lock.yaml,
                 снимок установленных runtime-файлов, предыдущее рабочее состояние.
```
- Изолированно собрать исходники: `workspace-groups` из чистого `8718d7f`; `cpamc-limits` с текущим xAI и регистрацией вкладок; `teratts` с обоими живыми TTS-фиксами и воспроизводимым vendor-diff; `web-mobile` сохранить из нынешнего работающего runtime и установить происхождение его отличия. Никаких `pnpm pack` прямо в каталог канонических архивов; lifecycle scripts и содержимое каждого `.tgz` проверяются после pack.
- Публиковать только новым именем, no-clobber и атомарно; сохранять sha256 и provenance. Режим `0444` ограничивает случайную запись, **но не защищает от владельца каталога/`chmod`**: дополнительно проверять отсутствие замены пути и hash перед каждой установкой. При необходимости абсолютной FS-иммутабельности нужен отдельный владелец каталога.
- Скопировать **весь необходимый профильный контекст** (`package.json`, lockfile, `pnpm-workspace.yaml`, patch, layout/настройки) в изолированный staging; применить одновременно все specs множества D, закрепив фактический `pnpm 11.22.0` (не предполагать pnpm 10). Построить lockfile только там, просмотреть весь diff; повторить `install --frozen-lockfile` и canary с проверкой host/client и bundle-list. Если clone не воспроизводит live layout, остановиться.
- Для отдельной будущей выкладки: сохранить исходную пару manifest+lockfile и runtime backup, перенести согласованную пару, выполнить **только** `dsh plugin --profile web-015 install --frozen-lockfile`; проверить разрешённые пути, установленные байты/хеши и `dsh.profile.bundles`; затем согласованный один рестарт по процедуре homelab и проверка в браузере. Не обещать, что неизменённые `file:`-пакеты физически не затронутся.
- Откат не должен считать архивы от 14 сентября рабочей версией: при неудаче восстановить исходную пару + живые runtime-снимки и реальное состояние сервиса по отдельному плану и разрешению, пока не создан первый известный исправный immutable release.

## 3. Verification Checklist (Definition of Done)
- [ ] Реестр активных плагинов и сравнение полного содержимого установленных пакетов с архивами; состав D зафиксирован, неожиданный drift блокирует подготовку.
- [ ] Версии, SHA-256 и provenance для каждого нового архива; тесты проходят на **распакованных** пакетах, сохранены TTS-фикс и mobile-изменение; source trees не затёрты.
- [ ] Только staging: согласованы manifest/lockfile, проверен diff, два последовательных frozen install дают ожидаемые runtime-файлы и bundle-list; негативный тест ловит старый/подменённый архив.
- [ ] Перед будущей выкладкой отдельно согласованы риск установки и отдельный single-use рестарт; прод не затронут на этапе подготовки.
- [ ] После будущей выкладки: граф/бандлы и фактический UI показывают цвет, xAI, Limits/API Keys, TTS и mobile; Host-эндпоинты и сервис проверены; rollback проверен на staging, не на живом профиле.
