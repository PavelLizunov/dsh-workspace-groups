# Spec: GitHub stable/latest для операторских DSH-плагинов (v2, на повторное ревью Pro)

## 1. Intent & Invariants
- Цель: сохранить исходники рабочих операторских плагинов в Git, испытать любое число GitHub pre-release, затем выпускать immutable stable; production всегда ставит только проверенные stable assets. Указатель GitHub `latest` — желаемая публичная точка входа, но updater сверяет его с максимальной подходящей SemVer и отказывает при несовпадении; pinned production не меняется автоматически.
- Нормативный снимок 14 упорядоченных bundles и 8 дополнительных dependencies — `github-release-inventory.json` (22 строки; tree SHA-256 установленного пакета, статус, источник, лицензия, стратегия). Оценки `unknown` и `stable_eligible=false` намеренны: подтверждение владельца/лицензии нужно до публикации. Два core bundles исключены. Desired set сейчас в точности `bundle_order` из inventory.
- Retired deps: `@deepseek-harness-tui/dsh-tui`, `dsh-better-sidebar`, `dsh-client-ui-session-id`, `dsh-homelab-overview`, `dsh-ouroboros`, `dsh-telegram` (все объявляют `dsh.bundle`), плюс `dsh-jev-supervisor` без bundle metadata. Они не включаются в release scope и должны исчезнуть из dependencies/lockfile в staging миграции, иначе `dsh plugin` воскресит шесть bundles; active patch rows проверяются отдельно. Ранее согласованное удаление Jev сохраняет данные, но не пакет.
- Strict stable: `MAJOR.MINOR.PATCH` в npm manifest и `vMAJOR.MINOR.PATCH` для single-package repo; никакого `-rc`, `-local`, `+local`, даты или повторного tag/version с другими байтами. Prerelease `MAJOR.MINOR.PATCH-rc.N`, `prerelease=true`, production запрещён. Binary baseline отдельно, не маскируется под stable.
- Эти этапы только проектные: никакого push/repo creation, смены видимости, GitHub Release, удаления live dependencies или установки в web-015 без отдельных решений оператора. Действующий DSH ядро `0.1.5-rc.2`; совместимость с ним обязательна, не означает совместимости со следующим DSH.

## 2. Interface / Data Contract
```text
Single-package: tag vX.Y.Z; in monorepo: <package>/vX.Y.Z.
Stable candidate: GitHub API list ALL releases (pagination), owner/repo pinned,
  draft=false, prerelease=false, immutable=true, strict package tag/namespace,
  one expected uploaded pnpm-pack .tgz + SHA256SUMS + provenance.json;
  choose max SemVer; for single-package repo /releases/latest MUST name this tag,
  otherwise fail closed; monorepo ignores repo-wide /latest.
Update: candidate > installed; equal+same digest=no-op; equal+different digest=abort;
  lower=abort (rollback separate exact tag+digest with operator approval).
Never use git:/github: dependency, GitHub autogenerated source archive,
  mutable URL, unverified symlink, or prerelease for production.
```
- `ai-gateway` remains private. Choose **independent namespaced tags** for `dsh-cpamc-limits`; per-package updater lists releases under that namespace, not repo-wide `/latest`. A future dedicated plugin repo (to get a per-plugin `latest`) requires the operator's separate repo/visibility decision. No automatic public mirror of gateway code. Pin exact subdirectory for pack and scan tar inventory for other gateway files and credentials.
- Eligibility gates by package: `workspace-groups` public fork with MIT attribution, upstream base and clean committed source (`HEAD 8718d7f`, tracked worktree clean at audit; earlier Pro claim of seven dirty files conflated untracked staging docs); existing `v0.1.0` prerelease has no assets and is not reused. `Fleet Cleaner` public main still requires dirty source/metadata/test changes committed and a new version; current public main requires removed `dsh-better-sidebar`. `cpamc-limits` private source contains dirty client/manifest and packaged KeyGuard vendor fix only in staging; commit and test standalone packed artifact before release. `TTS` and `mobile` remain `binary-only` local baselines (TTS license GPL-3.0-or-later, mobile MIT declared but source history unverified); do not create repos or stable Releases until formal source recovery, commit provenance, rebuild-equivalence/explicit divergence and owner's visibility choice. `dsh-ai-egress`, review packages, OpenViking status need separate license/source checks; third-party `dsh-codex-auth`, JSONL cache, memory plugin remain upstream-only until ownership established.
- Release chain: clean committed source + pinned build toolchain/frozen lockfile → tests → `pnpm pack` and exact packed inventory/license/secret scan → signed annotated tag (or independently verifiable protected build provenance) → enable immutable releases **before** release → draft + upload tgz/hash/provenance → download same bytes to canary → publish → verify `immutable=true`, GitHub release attestation, tag-peel full SHA, asset.digest and local SHA. No rebuild after canary. Existing local `*.local.*` archives remain recovery baselines, not stable Releases. Older installed local versions are migrated to new stable only after canary and operator decision (not treated as SemVer downgrade).
- `provenance.json`: schemaVersion, packageName/version, owner/repo+visibility, sourceCommit/full tag SHA, upstreamBase if fork, Node/pnpm/lockfile SHA, pack command, artifactName/SHA256/size, DSH compatibility, optional build-workflow ID. Asset, SHA256SUMS and provenance are cross-checked; release attestation/signature is independent trust anchor. `gh` here is 2.45.0 and lacks `release verify`; verify using a qualified newer CLI or official API/attestation verifier in isolated staging, NEVER pretend current `gh` already supports it. Repo immutability currently false for workspace-groups, ai-gateway and fleet-cleaner; stable blocked until enabled and verified.
- Private API: prefer narrowly scoped GitHub App installation credential, else temporary fine-grained Contents:read token. Never log or commit token; validate owner/repo, redirects, and GitHub API `digest=sha256`; 401/403/404/network/error fails closed. Cache at `/var/lib/dsh/.dsh/bundles/<owner>/<repo>/<package>/<version>/<sha256>/` via verified temporary file + fsync + no-clobber; source tarball_url/zipball_url forbidden. Production receives only exact local `file:*.tgz`, frozen lockfile, ordered bundle allowlist; no live GitHub access needed.
- DSH guard: before pnpm, scan every direct dependency's installed or staged manifest for `dsh.bundle`; reject if outside exact enabled allowlist, or if retired dependency still present. Stage removal of retired deps and patch rows as separate operator-approved deployment, retain old archives for rollback. Run profile `dsh plugin install` under a single operator guard with lock/snapshot; validate exact ordered bundle list after and fail/rollback if reappearing. No core DSH changes assumed.

## 3. Verification Checklist (Definition of Done)
- [ ] Review/complete `github-release-inventory.json` with explicit scope, ownership, license and source commit per operator package; unknowns exclude stable. Confirm retired list and patch effects with operator before deleting dependencies.
- [ ] For each source-backed candidate: clean repository, tests, signed or equivalently protected tag, immutable stable release, uploaded npm-packed artifact, attestation, asset digest and canary installing the **downloaded** bytes, independent of builder working tree.
- [ ] Negative canary checks: prerelease/draft/non-immutable, `/latest` drift, repo swap, altered asset, missing metadata, equal-version changed digest, older stable, private auth failure, offline GitHub, and six resurrected retired bundles all fail closed without live mutation.
- [ ] Published stable is verifiably restorable from GitHub even when local cache is absent; frozen lockfile reproduces same host/client hashes and exact ordered bundles on a clean DSH 0.1.5-rc.2 profile.
- [ ] Any future push, enable-immutability mutation, repo creation/visibility change, release publication and production switch are separate user decisions; DSH restarts need fresh one-use permission.
