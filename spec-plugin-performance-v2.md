# Spec: Измеримое облегчение работающих DSH-плагинов (v2 — техническое ревью Pro)

## 1. Intent & Invariants
- Цель: найти доказанные задержки/фоновую нагрузку семи активных non-core client modules и их Host-половин и предложить только минимальную настройку или малую правку существующего операторского плагина. Никаких форков, переписывания, новых зависимостей, изменений core, отключения полезных функций или действий в production в рамках Pro-ревью.
- Обязательные исходы исследования: «измеримый безопасный кандидат» **или** `NO SAFE MEASURABLE CHANGE`, если вклад мал/не измерен, bottleneck в core или меняется freshness/поведение. Размеры, Host RSS и периоды timers — только разведка, не решение.
- Нынешний `performance-baseline-web-015.json`: 60 графовых entries, 12,173,521 raw JS bytes, non-core 1,015,005 bytes (8.3%). Core PDF document-preview 6,888,478 raw / ~3,190,677 gzip bytes, ~95 ms warm loopback gzip по трём пробам. Host PID 264762 ~926 MiB RSS в момент замера; нет per-plugin attribution. База неполная для acceptance: нет browser fixture/trace, точных samples и контекста. Отказ от core document-preview запрещён: Files/Start/Markdown/PDF preview сохраняются; если core доминирует, только upstream issue, а не local patch.

## 2. Interface / Data Contract
```text
R0 static read-only: plugin graph/manifests/artefact SHA, source timers, existing logs.
R1 live observational: authenticated *existing* browser target only after human
   consent for CDP access, no Host restart/instrumentation; no causal claims.
C1 isolated canary: separate user approval for profile clone and new process;
   fixed DSH/runtime/browser/workload; only place for A/B or perf_hooks.
P1 production: OUT OF SCOPE; separate approval for artifact, install, restart.
```
- R1 privacy gate: approved existing authenticated CDP target only; never capture response bodies, cookies, Authorization/Set-Cookie, API-key content, unredacted query/session IDs/workspace paths, or screenshots when secrets may appear. Persist sanitized method, normalized endpoint, status, timing, `encodedDataLength`, initiator and task timings; raw trace `0600` with declared short retention and deletion. Do not create browser, transfer credentials, clear storage or use destructive API calls. If target/permission absent, R1 omitted and findings limited to R0. No load/flood testing active production.
- Timing modes: **browser-cold** = disable browser HTTP cache via CDP with existing cookies/storage/unchanged Host PID; **browser-warm** = cache on and discard first priming reload; do not mix results or call either Host-cold. Host-cold only separately approved canary. Live read-only Host: CPU, RSS/PSS, I/O, FDs, already emitted request timing; **no claim of event-loop delay** from `/proc`/systemd. Optional canary `node:perf_hooks.monitorEventLoopDelay()` and `eventLoopUtilization()` only after consent, never attach inspector to live Host.
- Scenarios chosen before instrumentation: S1 `navigationStart` → selected conversation visible, right sidebar control operable and input accepts interaction; S2 trusted click on Limits/API Keys/Fleet Cleaner/OpenViking → meaningful data/empty/error (not spinner); S3 active-tab click/keyboard → next paint of final content; S4 >=10-minute idle background: endpoint requests/minute, encoded bytes/minute, main-thread task ms/minute, long tasks/minute, safe handler timings if already available. One primary user-facing metric and practically meaningful improvement threshold `δ` per candidate fixed **before B**, other metrics guardrails incl quota freshness, CPU/RSS, error rate and privacy.
- Timer inventory is NOT a performance finding: workspace-groups visible-document 15 s config; OpenViking status 2.5 s active/15 s idle; Limits/Keys 60 s while mounted; Fleet Cleaner 15 s only while visible; mobile debug badge 1.5 s only with `?mobile-nav-debug=1`. DSH sidebar normally renders only active tab body per pane; check two panes/float/module timers, mount/visibility, endpoint/bytes/overlap, cleanup after hide. Visibility guard only if requests persist; dedupe only if concurrent equivalent requests exist; alter interval only if configurable and freshness requirement permits. Do not optimize Fleet/mobile-debug by timer alone.
- Separate attribution lane (minimal CDP Trace/Performance categories, not headline latency) from low-overhead timing lane (fixed DOM milestones/Performance timestamps, no full tracing). R1 live is observational only; never compare live «before» with canary «after» causally. Controlled C1 A/B: immutable A vs single attributable B, rest byte/config identical; pinned DSH profile, browser build/viewport/network/fixture; separate browser-cold/warm strata; >=3 discarded warmups, >=10 A-only pilot for variance, >=15 randomized paired AB/BA blocks; if CI imprecise vs precommitted `δ`, up to 30 pairs. Report raw samples, median paired delta, p50/p95, MAD, bootstrap 95% CI, failures; accept B only if CI excludes no gain, effect > δ and all guardrails/functions pass, otherwise NO CHANGE. Browser cache/carryover reset and competing activity documented.

## 3. Verification Checklist (Definition of Done)
- [ ] Baseline context includes SHA of live profile/lock/patch/installed packages, Host PID/uptime/load, browser build, viewport, cache, exact request timing and sanitized fixture identifiers. Existing three gzip samples are reconnaissance only until recorded.
- [ ] Operator separately approves R1 authenticated CDP (or it is skipped); tracing captures no credentials, session IDs, bodies or sensitive screenshots; no change to running DSH. C1 process and any instrumentation require separate approval, not Pro OK.
- [ ] Measured candidate matches a demonstrated symptom, has exact owner, small diff or existing setting, offline correctness/freshness tests and reversible immutable candidate package. No fork/rewrite/core edit or functional disable.
- [ ] Controlled A/B with holdout confirms user-visible delta above precommitted threshold and no regression; otherwise `NO SAFE MEASURABLE CHANGE` and upstream report if core dominates. No production step without fresh approval.
- [ ] GPT Pro gives explicit technical `OK` to the *plan*; this never authorizes CDP access, canary, source edit, GitHub release, profile install, or restart.
