# Spec: Измеримое облегчение действующих DSH-плагинов (v3, техническое ревью Pro)

## 1. Intent & Invariants
- Оптимизировать пользовательский отклик **только если** наблюдения и причинный canary A/B доказывают существенное улучшение. Без форков, переписывания, новых зависимостей, редактирования ядра или отключения функции; `NO SAFE MEASURABLE CHANGE` — равноправный результат.
- Семь non-core клиентских модулей только **включены и присутствуют в graph**, а не доказанно mounted или CPU-active. Снимок `performance-baseline-web-015.json`: 60 graph entries, 12,173,521 raw JS bytes, семь non-core суммарно 1,015,005 bytes (8.3%). Core PDF document-preview 6,888,478 raw, ~3,190,677 gzip и ~95 ms warm loopback (три разведочных пробы); размеры, Host RSS ~926 MiB и частоты таймеров не доказывают latency или attribution.
- Условия исследования: R0 статическое чтение существующих manifest/graph/логов; R1 наблюдение живого браузера только после отдельного согласия на authenticated CDP; C1 запуск инструментированного изолированного canary только после отдельного согласия; P1 production install/restart/source edits вне плана и требуют отдельного решения. Pro OK не разрешает переход между фазами.

## 2. Interface / Data Contract
```text
R0: immutable deployed source/graph hash, plugin timers as hypotheses only.
R1: live observational timings and safe aggregated request metadata; no causal
    claims, no raw CDP event persistence and no network/body/header traces.
C1: fixed exact DSH profile clone, one candidate B vs immutable A, randomized
    paired A/B and separately defined source/behavior tests; new Host process
    only with operator approval.
P1: separately approved deployment if C1 demonstrates meaningful improvement.
```
- R1 privacy: approved existing authenticated target only; collector MUST NOT enable response-body retrieval, Network extra-info, screenshots, DOM snapshots, console payloads or credential/header logging. In-memory allowlist maps CDP events directly to predeclared normalized route classes, aggregate status class, timing, byte counts, initiator category and main-thread task duration **before any write**; unknown fields/endpoints discarded; stdout/stderr have no event payloads, no raw trace persisted. Transient access to CDP metadata within collector must be disclosed in human consent; if zero transient sensitive exposure required, omit R1 network lane. Full raw tracing permitted only for an approved non-sensitive C1 fixture, not production R1.
- Timing names: `http-cache-disabled` = disable HTTP cache on same authenticated target, retain cookies/storage/Host PID; `http-cache-warm` = cache enabled with per-stratum priming run excluded. Service-worker/CacheStorage, code cache, browser process age and viewport recorded/held fixed. Neither is browser-process-cold or Host-cold; Host-cold instrumentation only in C1. Live Host metrics read-only CPU/RSS/PSS/I/O/FDs; event-loop delay/ELU unavailable without in-process metrics and only measured by `node:perf_hooks` in separately approved C1 (never attach to active Host).
- Predetermined user scenarios: S1 navigationStart → composite readiness `max(conversation visible, sidebar control usable, input interactable)` on one monotonic clock; S2 trusted click → first meaningful stable data/valid empty/error state for Limits, API Keys, Fleet Cleaner, OpenViking (not spinner); S3 click/key activate → first paint after defined terminal tab predicate (error counts as terminal but functional failure guardrail), S4 idle >=10 min → requests/encoded bytes/main-thread task ms/long tasks per minute. Before any B run freeze selector version, action source, timing domain, terminal predicate, paint/rAF rule, timeout and symmetric exclusion/failure handling; timeout/crash/error not silently dropped.
- Timer inventory (not findings): groups config 15s when document visible, OpenViking status 2.5s active/15s idle, Limits/Keys 60s while mounted, Fleet Cleaner 15s only visible, mobile 1.5s debug only under `?mobile-nav-debug=1`. Native dock renders active body per pane; check two panes/floats, mount lifecycle, overlap and cleanup. Candidate visibility fix only if hidden tab continues requests; dedupe only if equivalent concurrent calls measured; interval changes require a supported setting AND predeclared freshness contract. Do not disable document-preview (retains Files/Markdown/PDF); core bottleneck → upstream issue, no fork or patch.
- Distinguish **attribution lane** (minimal browser trace only on non-sensitive C1 for diagnosis) from **timing lane** (low-overhead DOM milestones/Performance entries, no full trace for headline metric). R0/R1 discover hypotheses only; one C1 confirmatory experiment pre-registers one B, one primary scenario, one primary metric, direction, meaningful improvement threshold `δ`, fixed N, paired estimator, all guardrail margins/window/estimator and privacy/function rules, reset/cache procedure, randomization seed, failures/exclusions; hash protocol before any B. Extra candidate/endpoint requires independent untouched confirmatory dataset (or predeclared multiplicity procedure); no post-data tuning.
- C1 process: pinned DSH/runtime/browser/viewport/fixture on clone with no production data; per condition × cache stratum >=3 discarded warmups; >=10 randomized paired A/A dry-run blocks to validate harness and choose fixed N **before B**. Then fixed N >=15 paired A/B blocks with independent randomized AB/BA order; never extend N after inspecting B CI. Publish all raw samples, paired deltas, median paired gain, descriptive p50/p95, MAD, paired-bootstrap 95% CI, failures. Accept B only if **lower 95% CI bound of predeclared paired improvement > δ** AND every functional/privacy/error/freshness/resource guardrail meets its **predeclared exact or non-inferiority bound** (direction, margin, window, estimator and failure handling fixed before B). Otherwise `NO SAFE MEASURABLE CHANGE`. p95 is descriptive unless primary metric with adequate separate design.

## 3. Verification Checklist (Definition of Done)
- [ ] R0 baseline anchored to profile/lock/patch and deployed artifact SHA, Host PID/uptime, browser build/viewport/cache/service-worker state and sanitized fixture metadata; no fabricated browser results; current graph/bundle samples remain exploratory.
- [ ] R1 authorized independently if needed; safe in-memory allowlist-only aggregates, no raw traces/bodies/headers/secrets; without consent/auth target skip R1, not bypass. No live service mutation or traffic flooding.
- [ ] C1 independently authorized, protocol pre-registered/hashed, A/A passed and fixed N frozen before B; no errors hidden, no ongoing auth/secret data copied; one attributable change and preserve behavior. Improvement only if lower CI > δ and all guardrails pass; else NO CHANGE.
- [ ] GPT Pro explicitly approves methodology alone; candidate implementation, archive publication, profile changes and restart remain separate human decisions.
